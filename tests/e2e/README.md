# GPU end-to-end tests

Thin test modules + fat helpers that exercise the real training and inference
entrypoints (`src/rfproteina/train.py`, `src/rfproteina/partial_autoencoder/train.py`,
`src/rfproteina/generate.py`) as subprocesses on GPUs. Modeled on
`protein-foundation-models/tests/e2e`.

## What runs

| Test | Marker(s) | What it does |
|------|-----------|--------------|
| `test_gpu_regression.py` | `gpu, regression, slow` | Compares against committed H200 baselines: SOTA and AE training (25 optimizer steps from random initialization), inference (one MCSA example), and unindexed-motif beam search. A separate GPU-suite preflight checks the checkpoint pair selected by `configs/inference.yaml`. |
| `test_gradient_coverage.py` | `gpu` | Training smoke: trains briefly and asserts no parameter is silently disconnected (a feature behind an all-false mask gets an exactly-zero grad, so `grad is None` never fires). |
| `test_af3_structure_quality.py` | `gpu` | Refolds pre-cutoff crystals (PTM, HEM, N-glycan, custom CCD, protein–DNA, RNA) and checks RMSD, bonds, and clashes. |
| `test_af2_acceptance.py` | `gpu, slow` | End-to-end acceptance coverage for the launcher-owned AF2 worker pool. |
| `test_entrypoint_imports_resolve.py` | *(none — CPU)* | Resolves each entrypoint's `from rfproteina.* import ...` against the real modules in about a second, so a stale import isn't first discovered minutes into a GPU allocation. |
| `test_entrypoints_resolve_configs.py` | *(none — CPU)* | Runs each hydra entrypoint's `--help` to prove it still finds `configs/` from its location under `src/`. |
| `test_slurm_launchers.py` | `cluster` | `bash -n` syntax check of the SLURM launcher scripts (no GPU, no job submission). |

Baselines for `test_gpu_regression.py` are generated by
`src/script_utils/generate_e2e_baselines.py` and committed under `tests/e2e/baselines/`.
Training regressions use the current `experiment=sota` and `experiment_ae=sota` recipes;
inference and search use the checkpoint pair selected by `configs/inference.yaml`.
The LoRA regression starts from `pretrain_ckpt_path` in `experiment=sota_finetune`.
Stage that checkpoint under `DATA_PATH` too.
Training loss regressions use batch size 2 with compilation disabled. Flow loss
and gradient-coverage tests use exploration k=1; release recipes retain their own settings.
See `tests/test_oracles.py` for full oracle unit/integration tests.

The shared `deterministic_env()` runs regression, AF2 acceptance, gradient-coverage,
and baseline-generation subprocesses eagerly with `TORCHDYNAMO_DISABLE=1`.
This also disables RMSNorm's independent compile wrapper, which is not controlled
by `use_torch_compile=false` or `compile_lengths=null`. For an equivalent standalone
run, use `TORCHDYNAMO_DISABLE=1 rfd4-generate ... compile_lengths=null`.

## Running the regression suite

Run from the repository root in an environment with the project and pytest installed,
on an allocated GPU node. Set `DATA_PATH` to the data and checkpoint root before
running. Training also needs the datasets selected by the release configurations.
The committed regression baselines require an H200; those comparisons skip on other
GPU models. Use the same hardware and dependencies when comparing results.

```bash
# All regression checks, including checkpoint preflight:
RUN_GPU_E2E_TESTS=1 pytest -v tests/e2e/test_gpu_regression.py

# Just the flow training regression:
RUN_GPU_E2E_TESTS=1 pytest -v \
  tests/e2e/test_gpu_regression.py::test_sota_training_regression

# Just the AE training regression:
RUN_GPU_E2E_TESTS=1 pytest -v \
  tests/e2e/test_gpu_regression.py::test_ae_training_regression
```

GPU tests require `RUN_GPU_E2E_TESTS=1`. Tests requesting multiple GPUs also
check the available count. `ALLOW_SINGLE_GPU_E2E=1` bypasses that count guard
for a compatible single-GPU run; it does not provide CPU execution.

Missing released checkpoints or training baselines are failures. Missing inference
or beam-search baselines cause those comparisons to skip. Inspect the skip summary
when interpreting a passing test run; skipped tests do not establish compatibility.
Do not regenerate baselines to resolve an unexplained regression.

## Oracle tests and CI

AF2 and AF3 tests additionally need their runtime images, model weights, caches,
and launcher daemons. These dependencies are separate from the core Python install.
See the test fixtures for the requirements of each oracle test.

IPD runner profiles, container setup, and daemon startup are documented in
[the internal GPU testing guide](../../.ipd/docs/gpu-tests.md), when `.ipd` is present.
The CI implementation lives in `.github/workflows/lint_and_test.yaml` and
`.github/ci/run_gpu_tests.sh`.
